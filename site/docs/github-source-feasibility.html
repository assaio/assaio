GitHub source feasibility and bounded review dismissals

assaio-agent evidence --github adds raw review-dismissal observations to local delivery evidence. They describe a source-stated PR outcome, never an AI session result. Exact review rounds, comparable workflow lifetimes and CI rates, authoritative one-parent merge methods and explicit PR revert relations remain deferred under B232.

This guide records a finite source study captured on 2026-10-10. Field availability, observed cases and comparable measurement populations are separate questions. A schema capture answers only the first.

Currently shipped reads

Two fixed GraphQL repository walks run through the user's own gh, ordered by PR updatedAt, newest first. --since bounds that update-time walk, not every event's occurrence time. The base walk reads 50 PRs per page, at most 20 pages, plus a top reread of at most 20 pages. The independent history walk reads 5 PRs per page with the same page and reread caps. Both share one invocation observedAt, while retaining separate PR counts and read-back windows. Repository totals cover all repository PRs, rather than the selected window. Each API call has a 60-second timeout and an 8 MiB response cap. Source errors fail the document.

Only PRs named by candidates or alternatives receive details. Historical data joins by PR node id and number only when commit totals and returned first-100 SHA sets agree, without duplicate SHAs in either prefix. Matching truncated prefixes do not establish complete history; a mismatch withholds the join.

Dismissal coverage preserves five distinct facts:

Field Meaning
totalCount All PR timeline events, including kinds outside the dismissal filter.
filteredCount All selected review-dismissal events in that timeline.
pageCount The source-reported count in the returned selected slice.
listed Actual retained dismissal nodes.
hasPreviousPage Source-stated truncation of the selected dismissal population.

For the production last: 100 read, usable coverage requires consistent nonnegative counts, listed = pageCount = min(filteredCount, 100) and hasPreviousPage = (filteredCount > pageCount). Missing coverage remains null/unavailable; independently validated raw events may still appear. An explicit usable connection with filteredCount = 0, an empty slice and no previous page establishes selected absence for that PR at capture time, even when totalCount is positive.

A dismissal carries its opaque event id, PR number, source-stated previous review state and actual dismissal time. A null review leaves review id, reviewed commit hash and submission time absent. The envelope retains gh source, parsed provenance, local-only privacy and the shared invocation observation time. The event belongs to the PR outcome layer. Its previous state does not restore a current review snapshot or enter a new count-derived metric or rate.

No author, actor, reviewer, dismissal message, title, body, content or person field is selected. Requests send repository identity and cursors, never session or store data. Observations remain in memory for one command, outside the store, sync, dashboards, share and plugins. See PRIVACY.md, the evidence guide and ADR 0025.

CheckSuite and WorkflowRun document the schema associations, without establishing comparable PR lifetimes. MergedEvent and AutoMergeRequest support the landing-commit and requested-method distinction. CrossReferencedEvent describes references; revertPullRequest is a mutation, not a read-side revert relation.

All three positives include review id, actual submission time and reviewed commit hash. These cases establish approved→dismissed observations, not every possible previous state or join shape.

The study's newest-by-update 30 CLI PRs of all states and separate newest-by-update 30 merged CLI PRs each had zero selected dismissal events while other timeline events were present (cli-dismissal-root-page1.json, cli-dismissal-merged-root-page1.json). The samples overlap and are not 60 distinct PRs. Their source totals were 4,703 all PRs and 3,267 merged PRs. The separate 30-merged-PR count captures found one selected dismissal in github/docs and two in microsoft/vscode (github-docs-dismissal-counts.json, vscode-dismissal-counts.json), with source merged-PR totals of 15,616 and 55,268. These are finite observed populations; none establishes API incapability or absence throughout a repository or GitHub.

For github/docs #46200, dismissal-truncation.graphql and github-docs-dismissal-truncation.json compare investigative last: 0 and last: 1 reads. The zero slice reports total 23, filtered 1, page 0 and previous page true; the one slice retains the event and reports previous page false. This demonstrates count distinctions and source-stated truncation. last: 0 is never the production query and does not prove a real population exceeding 100 dismissals.

The initial pr-timeline.graphql investigation read 10 PRs per repository. In assaio/assaio, source total 106, it returned 11 force-push events, 9 merged events, 5 cross-references, 5 review requests and no dismissals (assaio-timeline-page1.json). In cli/cli, source total 4,703, it returned 13 review nodes, 25 review requests, 11 removals, 19 cross-references and no dismissals (cli-timeline-page1.json). Its first-10 commits, first-50 reviews and last-100 mixed timeline slice are investigation bounds, not the production read contract.

schema-pr-response.json, schema-transitions-response.json and schema-workflow-response.json record schema availability. They neither recover missing histories nor establish semantic comparability. Synthetic conformance cases remain separate from real source captures and cannot close any of the real-corpus gaps above. No feature test or release-gate execution is asserted by this source study.

Remaining B232 gates

B232 remains open. Review rounds require authoritative transitions and round boundaries, explicit coverage and real cases including changes_requested dismissals, null joins and selected truncation beyond 100. Comparable workflow lifetimes require a source that covers lost and force-pushed commits, attempts and relevant PR associations, with comparable populations and real positive, negative and unknown cases. One-parent merge methods require an authoritative applied method source and distinguishable real squash/rebase cases. Revert relations require an explicit content-free read-side relation and real original/revert, negative and unknown cases.

Current review snapshot calculations, offline session-commit/v2 and GitHub session-commit/v3 matching remain unchanged. The addition is reversible by reverting one feature PR; it needs no store migration. Published tags remain immutable. See ADR 0024 and ADR 0025.
