Is it delivering?

Teams pour real money into AI coding tools and can't answer the one question that matters. Vendor dashboards count tokens and dollars — spend, never output — one silo per tool. assaio reads the session logs already on your machine and weighs what AI produced against the tokens it burns — per project: effectiveness, model fit, context health, adoption, and how efficiently tokens turn into shipped code. Claude Code, Codex, Gemini CLI, Copilot CLI, Cline. Offline, no account, no upload — the first piece of a self-hosted AI-engineering analytics platform.

What it measures — and what it doesn't yet

the honest scope

assaio measures how much AI is producing, how efficiently, and with how much friction — not how good the result is. That line is deliberate; blurring it would be the easiest way to lie with this tool.

The second easiest way is a zero. Your tools do not all record the same things, and a field one of them never writes arrives here looking exactly like a measurement of nothing. Read naively, a Cline or Copilot window said 100% of your sessions were conversational — a sentence about how someone worked, drawn from a column their tool does not keep. Since v0.10 that cannot happen: every figure is computed only over the sources that record its field, says how much of your window that reaches, and withholds the verdict rather than certifying a silence.

Measured today · offline

Adoption
Tool mix, sessions, and sub-agent delegation — from the session logs.
Effect
AI lines added and removed, from diff +/- markers. The code text itself is never read or stored — only counts.
Efficiency
Lines of code per token spent — where the context window earns its keep. Cost per 100 lines too, as an honest estimate, never the headline.
Friction
Edit/write tool-calls, plus proposals the human declined.

Not measured yet · needs the server stage

  • Survival — whether AI-written code lived on in main after review, rewrites, and reverts.
  • Bug impact — whether it caused bugs, only ever against age-matched human code.
  • Quality — maintainability, alongside DORA- and DX-style signals.

These need correlating usage with git and issue history — the deeper server work ahead. The local survival command (v0.2) is the first honest step, and v0.8 puts a git evidence collector under it: every commit in the window becomes a content-free observation — counts and a file-category split, never a path or a message — which is what an attribution edge will eventually point at. v0.9 adds the conformance corpus that defines what an honest link is before the engine exists: ten scenarios — including two where the evidence genuinely cannot decide — asserting that ambiguous stays ambiguous and that a human’s correction wins.

Since v0.5 every verdict carries a confidence envelope — activity, pricing and turn-level coverage, the sample it rests on, how fresh the data is, and which build read it — so a thin read cannot be quoted as a solid one. Since v0.9 it carries a fourth axis, signal coverage: how much of your window that particular figure actually reaches. A reasoning share read off under 1% of your output now says so instead of reporting high, and a metric nothing in the window can answer reads insufficient rather than confident — and since v0.10 it says which nothing: a window that cannot answer, a count of zero, or a plugin that never said what it rests on. Since v0.6 every one of them can also be read per kind of work: label a session with mark and $/100 lines on bugfixes stops being averaged in with research and greenfield features. Write your own metric plugin in any language and it renders right beside the built-ins, carrying the same envelope.

The Assay — an offline dashboard

one self-contained file

assaio-agent dashboard writes a single self-contained HTML file: a verdict faceplate, a bounded top-project drill-down by repository subpath, model and tool mix, and a cost-basis colophon. Light and dark. Project and member names are pseudonymized by default, so it is safe to hand to a teammate or paste into a review — --no-anonymize for real names, which never leave your machine.

Self-contained

No network, no CDN — one file you can open offline or attach to an email. The same posture as this page.

Shareable by default

Pseudonymized project and member names; a per-member team section appears only on a central store.

Honest on its face

Every cost marked an estimate; unpriced usage flagged, never a fake $0; a "how to read" note per section.

Commands

one binary

initA first run end to end: detects your tools, prints every directory it will read before reading it, imports, reports, and names what to run next. No config needed.
demoFull reports on bundled sample data — the 60-second first look, no logs needed.
backfillImport local session logs. Incremental: an input already read unchanged is skipped; --full forces a re-parse.
reportToken/cost report. --by day|project|tool|model|entrypoint|member, --format table|json|csv, --compare.
effectivenessAI output vs cost — AI lines, edits, rejections, $/100 lines — per project.
analyzeRun the metric validators (and any metric plugins); print each one's directional read. --task|--outcome|--difficulty recompute every one over just the sessions you labeled that way.
markLabel a session with what the work actually was — task class, outcome, difficulty. Category values only, never free text, never synced; the one fact the logs cannot contain.
signalsWhat assaio can report, and what your data supports. describe says what one signal counts and what a zero means; coverage reads your store and reports each signal as fully, partly or not at all supported — because "no rework happened" and "this source never recorded rework" are different facts.
survivalDirectional local outcome: how much of a repo's window still lives in HEAD, beside its AI lines — and, since v0.8, what those commits changed by category (test / source / docs / config / generated) plus how many were reverts. Read from content-free commit observations: no path, branch name, message or diff leaves the repository. Since v0.9 merge commits are reported apart from the rate — git publishes no line counts for a merge, so a hand-resolved conflict is counted in neither figure rather than inflating survival.
dashboardWrite the self-contained offline HTML Assay report; pseudonymized by default.
checkExit non-zero over a token (or API-equivalent $) budget — a CI / pre-push gate. Also runs your rule plugins: an error alert, or a rule that could not be evaluated, fails the gate.
explainThe long-form page for a metric — what it measures, how to read it, what to do, and its limits. Needs no store.
statuslineOne ambient line for your status bar: today's tokens, AI lines, cost basis and data age. Read-only, never fails loudly.
serve · syncSelf-hosted team server and the push to it — pseudonymous by default.
doctor · statusDetected tools, resolved log roots, store size, the per-source depth matrix, and format-drift canaries. doctor --strict exits non-zero on suspected drift — for cron.
plugins · metricslist / verify out-of-tree exec parser, metric and rule plugins — nothing stored.
config · clear · compactPrint the effective config; delete stored data with an explicit scope and --yes; return freed pages to the filesystem.

"Supports Gemini CLI" is misleading when it means tokens but no edits. Since v0.5 each source publishes its real depth — deep (tokens + activity), standard (reliable usage, documented activity gaps), import-only — and doctor prints the matrix for the tools found on your machine. Since v0.7 a source declares that per signal rather than per tier, because "has activity" is one bit over a tool that records changed lines and no edit count, no tool calls and no turns — so signals coverage tells you which of the twenty figures your own data can actually carry. The first thing that bought, in v0.8: the catalog had been claiming every source reports reasoning tokens, where only three of five do. In v0.10 it became a rule the metrics obey rather than a table they sit beside — a figure is computed only over the sources that record its field, so a tool that never writes an edit count is absent from the session mix instead of counted as a conversation.

  • AI-line activity (lines, edits, rework) is captured in full for Claude Code and Codex; Copilot CLI carries changed lines only — its log names tool calls too, which v0.10’s field audit found and assaio does not read yet — and Gemini CLI and Cline contribute cost but no line counts. signals coverage reports which of the twenty figures your own mix supports.
  • Copilot CLI totals a session only when it ends, so its records cover a whole session rather than a turn: they carry lines added and removed, are marked ‡ in reports, and lower the turn-level coverage every verdict declares.
  • Format drift is detected rather than silently absorbed: four per-source canaries compare each import against a baseline of recent runs and warn when a vendor changes a log format under you.
  • Cline is discovered across VS Code, Insiders, VSCodium, and Cursor. Costs come from a vendored snapshot of the LiteLLM price table.
  • The price table is flat per model — long-context (e.g. [1m]) and 1-hour cache premiums aren't modeled yet, so heavy-context sessions under-estimate.
  • A model missing from the table renders — (JSON null, CSV blank, excluded from totals) — never a faked $0. doctor prints every caveat on each run.

More sources — opencode, Aider, Qwen, Roo & Kilo Code — are on the roadmap and buildable out-of-tree today.

Cost honesty & the team server

estimate, not invoice

Every $ is an estimate

Priced at public pay-as-you-go rates — not your bill. Token counts are computed server-side and unobservable to an offline client.

Declare your real basis

On a subscription or negotiated rate? Set pricing — an effective $/token or a monthly plan cost — and reports show a truer figure. subscription-fit then reads whether the plan pays off.

Budget gate

check --max-tokens N exits non-zero over budget — plan-independent by default, for CI or a pre-push hook.

Team server, self-hosted

serve pools usage that teammates sync to it and serves one aggregated, pseudonymized-by-default dashboard. You host it, on infrastructure you control.

Adapt it to your organization

built to extend

One tool = one package; one metric = one file. Extend assaio without forking — exec plugins are standalone executables in any language, declared in your config and speaking a small stdout protocol, so they survive core refactors. Three protocols today — data sources, metrics, and rules that gate CI.

Data source · any language

An out-of-tree parser — Python, Rust, shell — for a tool assaio doesn't read yet. plugins verify checks conformance. Or add one in-tree via PR.

Metric plugin · any language

An analyzer that reads the same prepared data every built-in metric reads and returns one result — it renders in analyze and on the dashboard, no rebuild.

Rule plugin · any language

A gate of your own: it reads this window's verdicts — never usage rows, never project names — and raises alerts that can fail check in CI.

Query the store

The SQLite schema is documented — query it with sqlite3 or any client, or pipe report --format json|csv into your own BI.

Privacy first — and what it will never do

refusals

Local analysis never touches the network — no account, no telemetry, no upload. assaio reads token and line counts, never your prompts or your code. The store holds a project basename, never a full path.

  • No "estimated time saved." The logs contain no counterfactual, so any such number is invented.
  • No leaderboards. Nothing is ranked per named individual — aggregate and pseudonymized by default.
  • No silent precision. Directional signals say so; an unpriced model renders a blank, never a fake $0.
  • No per-person analytics outside a deliberate, governed team-mode opt-in.

Why "assaio"?

assay + io

An assay is the metallurgist's test: what a piece of ore is actually worth.

Ore can glitter and still be worthless. That is precisely the question engineering organizations face with AI coding tools — plenty of glitter, tokens burned and dashboards full of activity, and very little honest measurement of what any of it is worth.

assaio is built to be that test. It measures the real value in the ore, and it would rather show you an honest blank than a precise-looking number that is wrong. The metaphor sets the ethics too: an assay examines the metal, never the miner. assaio measures value, not people.
